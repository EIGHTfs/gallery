# 20261014 图片缓存方案（gallery）

> 状态：**已确认路线 A（先做 HTTP 缓存）**，待执行。
> 范围：只做服务端 HTTP 缓存头 + 条件请求（304）；页面不改渲染逻辑，不引第三方库。
> 后续可选：缩略图、IndexedDB/localForage 持久缓存（见第十节）。

---

## 一、修改目标

- **问题**：gallery 每次刷新都要重新加载图片。
- **现状取证（真模块调用，非推断）**：
  - 出图走 `server/lib/util.js` 的 `streamFile()`，唯一调用点 `server/routes/browse.js` 的 `/api/media`
  - 实测响应头：`{"Content-Type":"image/jpeg","Cache-Control":"no-cache","Content-Length":1024}` —— **无 ETag、无 Last-Modified**
  - `no-cache` 语义 = 每次必须回源校验；而**没有任何校验器**可校验 ⇒ 只能整份重新下载
  - 对照：静态资源（非 html）走 `server/core/app.js` 的 `public, max-age=3600` ✓，**图片漏了**
  - 图片 URL 稳定（无 `?t=` 时间戳；`normalizeFavSrc` 只做同源化）⇒ HTTP 缓存本可生效
  - 附带发现：列表**直接加载原图**（`server/public/app.js` 中 `src: window.API.apiUrl(im.url)`，`im.url = /api/media?file=<原图绝对路径>`），项目无缩略图机制。`loading="lazy"` 已有。
- **期望效果**：
  1. 刷新时未变更的图片**不再产生网络流量**（命中缓存；必要时仅 304 空响应）
  2. 图片文件被替换后自动失效重下，不会看到旧图
- **成功标准（可验证）**：
  - `curl -I /api/media?file=...` 返回 `ETag` + `Last-Modified` + `Cache-Control: public, max-age=…`
  - 带 `If-None-Match: <etag>` 重复请求 ⇒ **304**，响应体 0 字节
  - 浏览器二次刷新：图片为 `304` 或 `(disk cache)`，`transferSize = 0`；服务端无对应读盘
  - 现有测试 6/6 不回归；gallery ↔ 模板逐字节一致

## 二、潜在问题分析

| 风险类型 | 可能性 | 影响 | 缓解措施 |
|---|---|---|---|
| 兼容性破坏 | 低 | `streamFile` 加参会波及调用点 | 调用点仅 1 处；新参数可省略，保持向后兼容 |
| 看到旧图（缓存陈旧） | 中 | 同一路径换图仍吃旧缓存 | ETag = `size-mtimeMs`；max-age 取 1 天 + `must-revalidate` |
| 安全 | 低 | 缓存被共享代理留存 | `/api/media` 在 `publicRoutes`（`guestPages:true`，游客可读）⇒ 用 `public` 与静态资源同口径；将来若收紧登录门应改 `private` |
| 性能倒退 | 低 | 每请求多一次 stat | `streamFile` 本就要 `fs.stat`，零新增 IO |
| 依赖冲突 | 无 | 零依赖项目 | 本方案不引任何依赖 |

**边界条件（≥3）**：
1. `If-None-Match` 传 `*` / 逗号列表 / 弱校验 `W/` ⇒ 需按 RFC 做集合匹配，不能只做字符串相等
2. mtime 精度：CIFS/FAT 可能秒级 ⇒ 用 `size + mtimeMs` 双因子缓解
3. `stat` 与 `createReadStream` 之间文件被换/删 ⇒ 现有 404 兜底仍在；有可接受窗口
4. `If-None-Match` 与 `If-Modified-Since` 同时存在 ⇒ RFC 规定前者优先
5. 首次访问并发 N 张大图 ⇒ 缓存只帮第二次；首屏重量需缩略图（第十节）
6. `Range` 请求当前不支持（`streamFile` 无 Range）⇒ 本次不做

### 附：localForage 评估（C 方案依据）

- 定位：**存储抽象层**（IDB → WebSQL → localStorage 降级），只管存取，**不决定何时发请求**。对「刷新重新下载」本问题无直接作用。
- 本机已有现成副本（无需下载）：`spine-multi-viewer/public/vendor/localforage.min.js`、`dsh-theme-mediascape/assets/vendor/localforage.min.js`，均为 **1.10.0 / 29,703 字节 / Apache-2.0**（另需随带 LICENSE）。
- 我们已有先例：`dsh-theme-mediascape` 的 `lib/client.js` 内联 localforage@1.10.0，`lib/client-parts/foundation/utils.js` 用它做媒体缓存，并用自研 `__meta`（`lastUsed` + 字节预算）实现 LRU 逐出。
- 结论：**若将来做 C 方案，localForage 是合理选择**，但必须同时满足四条：① 强制 `setDriver(INDEXEDDB)`，失败静默降级（绝不落 localStorage 存图）② 自研 LRU + 容量，容量走服务端配置下发（不硬编码）③ 首帧仍走网络、命中后台切 blob ④ 只缓存**缩略图**，不缓存原图。

## 五、逐文件改动详情

### 5.1 `server/lib/util.js` — `streamFile()`

- **当前逻辑**：`fs.stat` → 头只设 `Content-Type` + `Cache-Control: no-cache`（+ 有 size 时 `Content-Length`）→ `createReadStream().pipe(res)`
- **改动**：
  1. 新增可选参数（如 `reqHeaders`），不传时行为与现在完全一致（向后兼容）
  2. `stat` 成功后计算 `etag = '"' + st.size + "-" + Math.floor(st.mtimeMs) + '"'`
  3. 条件命中（RFC 优先级）：`If-None-Match` 集合包含该 ETag 或 `*` ⇒ 回 **304**（带 ETag/Last-Modified/Cache-Control，无响应体）；否则再看 `If-Modified-Since` ≥ mtime（秒级截断）⇒ 304
  4. 200 分支头改为：`Cache-Control: public, max-age=<常量>, must-revalidate`、`ETag`、`Last-Modified`
- **原因**：给浏览器可用的校验器 + 允许缓存；304 让「刷新」变零流量
- **影响**：`jsonRes` 与其它调用不受影响（只改 `streamFile`）

### 5.2 `server/routes/browse.js` — `apiMedia()`

- **改动**：签名加第三个参数（请求头），仅取 `if-none-match` / `if-modified-since` 两个值透传给 `streamFile`
- **原因**：条件请求需要请求头；只传两个头值可保持 lib 层不依赖 req 对象

### 5.3 `server/app.js` — 路由接线

- **改动**：`"GET /media": (req, res, c) => browse.apiMedia(c.query, res, req.headers)`
- **原因**：`req` 已在处理器作用域内（1 行接通）

### 5.4 `test/media-cache-headers.test.cjs`（新增）

隔离测试（按 `test-design-norms`：临时目录造夹具、不碰真实素材、相对路径）：
1. 200 时头含 `ETag` / `Last-Modified` / `max-age`
2. `If-None-Match` 命中 ⇒ 304 且 0 字节体
3. 文件 mtime/size 变 ⇒ ETag 变 ⇒ 200
4. `If-None-Match: *` ⇒ 304
5. 弱校验 `W/"..."` ⇒ 能匹配
6. 文件不存在 ⇒ 404

### 5.5 `docs/20261014-图片缓存方案.MD`（新增）

本方案入库。

### 5.6（可选 Step 5）`server/lib/gif.js`、`server/lib/archive.js`

zip/rar 内嵌图片与 gif 输出同样写死 `no-cache` ⇒ 用**归档文件自身 mtime+size** 做 ETag，统一加缓存头。

## 十二、经验固化（硬要求）

预期固化 1 条，**优先追加进 `media-persist-cache`**（先查重，不新建重复 skill）：

```
现象：网站在浏览器里每次刷新都重新下载图片
根因：图片接口写死 Cache-Control: no-cache，且未发 ETag / Last-Modified ——
      没有校验器可校验 ⇒ 浏览器只能整份重下（no-cache ≠ 不缓存，而是「每次必须回源校验」）
解决：响应用 ETag = "<size>-<mtimeMs>" + Last-Modified + Cache-Control: public, max-age=…, must-revalidate，
      并实现 If-None-Match / If-Modified-Since 条件请求返回 304（RFC：If-None-Match 优先）
防再犯：改任何「文件/图片/媒体输出」端点时，先 curl -I 看有没有 ETag/Last-Modified；
      缺了就按 ETag=(size-mtimeMs) 补上；判据写进 code review 清单
```

落点：`ai-work-archive/skills/<分类>/media-persist-cache.md`（追加），并同步 `.dsh/skills/` 生效副本后提交。
